# Cut List Maker

CM動画をドロップすると、**カットの切り替わりを自動検出**して、
**各カットで一番「そのカットらしい」1枚**を静止画で書き出し、
**AIが絵を見てCMコンテのト書きを書き**、**ナレーションを聞き取って各カットに載せ**、
**コンテのPPTX・カット表Excelまで作る** ツールです。

**ブラウザで開くだけで使えます → https://rinpoko.github.io/cut-list-maker/**
（Mac / Windows 用のアプリ版もあります）

10カットのCMなら10枚。1本15秒のCMで、画像だけなら数秒、ト書き＋PPTXまで含めて30〜40秒です。

## ブラウザ版（PWA）

### 開く

**https://rinpoko.github.io/cut-list-maker/**

### アプリとして入れる（任意）

URLを開いたあと、

- **Mac / Windows の Chrome・Edge**: アドレスバー右端の **インストールアイコン**、
  または画面右上の「アプリとして入れる」ボタン
- **iPhone / iPad の Safari**: 共有ボタン →「ホーム画面に追加」

入れると、普通のアプリのように独立したウィンドウで開き、Dock や
ホーム画面からも起動できます。一度開いておけば**オフラインでも起動します**
（AIを使う処理だけは通信が必要です）。

### 動画はアップロードされません

解析はすべて**あなたの端末のブラウザの中**で動きます。動画ファイルが
サーバーに送られることはありません。送信するのは AI を使うときだけで、
そのとき Gemini に渡すのは

- 候補フレームを並べた小さな画像（コンタクトシート）
- 選ばれたカットの縮小画像
- ナレーション用の音声（モノラル16kHzに落としたもの）

だけです。APIキーもあなたのブラウザの中（localStorage）にだけ保存され、
このサイトのサーバーには送られません。

### 書き出し先

- **Chrome / Edge**: 書き出すたびにフォルダを選ぶダイアログが出て、
  そのフォルダへ直接書き出します（デスクトップ版と同じ）
- **Safari / Firefox**: まとめて **ZIP でダウンロード**します

### 速さ

ブラウザのハードウェア再生支援（WebCodecs）を使っているので、
デスクトップ版と同じか少し速いくらいです。
10秒のCM・7カットで、画像の書き出しまで **約1.7秒**（AI無し）。

### 必要な環境

Chrome / Edge 94以降、Safari 16.4以降、Firefox 130以降。
WebCodecs に対応していないブラウザでは、遅い代替手段に自動で切り替わります。

### 確認済みの動作（公開URLで実測）

| 素材 | 判定したfps | 検出したカット | 正解 |
|---|---|---|---|
| 通常のMP4（NLE書き出し相当・10.1秒） | 25.000 | 7 | 7（境界も一致） |
| 断片化MP4（ブラウザ録画・5.0秒） | 24.10 | 5 | 5（境界も一致） |

PPTX・カット表Excel・一覧シート・`_report.json` の書き出し、
Gemini への疎通（CORS）、Service Worker の登録、
フォルダへの直接書き出しの可否判定まで確認済みです。

### macOS（Apple Silicon）

まっさらなMacでもそのまま動きます（Apple Silicon 用）。

`dist/Cut List Maker-1.5.0-Windows.zip` を解凍し、出てきた
**「Cut List Maker」フォルダごと**デスクトップなど好きな場所に置いて、
中の **`Cut List Maker.exe`** をダブルクリックするだけです。

- **インストーラーはありません。管理者権限も要りません。**

## ト書きの自動生成

カットを選定したあと、**選ばれた絵をAIがもう一度見て**、各カットのト書きを書きます。
1本まとめて渡すので、前後がつながった読めるコンテになります。

プロンプトには実際のCMコンテ／シナリオの作法を入れてあります。

- 現在形で書く
- 体言止めを基本に短く言い切る（10〜25文字）
- 書くのは**目に見えるものだけ** — 場所・状況、人物の配置と動作、小道具・商品、画の作り
- 書かないもの — 心理描写（悲しむ・喜ぶ）、セリフの文言、「何か」のような曖昧語、推測

実際の出力例（テスト映像より）:

```
カット01 (1.6s)  カラーバーに走る斜めの光線
カット05 (1.8s)  黒背景に浮かぶ赤と緑の粒子
カット10 (2.1s)  画面いっぱいに広がるカラーバー
```

参考にした作法: [シネマドライブ「上手いト書き」](https://cinemadrive.jp/kikaku/2927/) /
[ぺんくり「テレビCMの絵コンテの書き方」](https://pencre.com/ekonte-kakikata/)

## ナレーションの音声認識

動画の音声を取り出して Gemini に聞かせ、**ナレーションとセリフを時刻付きで書き起こし**ます。
書き起こした文は、**それが実際に聞こえているカットに置かれます**。

1つのナレーションが複数カットにまたがるときは、**フレーズごとに分けて別々のカットに置きます**。
まとめて先頭のカットに書いてしまうと、絵と言葉がずれてしまうためです。

- Gemini には読点・句点・息継ぎで細かく区切って、区切りごとの時刻を返させます
- それでも長いまま返ってきた場合は、読点・句点で分けて、文字数の進み具合から
  各フレーズの時間帯を見積もります
- 置き場所は**重なっている時間がいちばん長いカット**で決めます。
  カットの変わり目の数十ミリ秒手前から声が出るのは普通にあるので、
  読み始めた時刻だけで決めると1つ前のカットに寄ってしまいます

実例（テスト映像）:

| カット | 尺 | ナレーション |
|---|---|---|
| カット01 | 0.00–1.60秒 | 制約も、 |
| カット02 | 1.60–2.80秒 | 逆境も、 |
| カット03 | 2.80–4.80秒 | これまでの常識も。 |
| カット05 | 5.80–7.60秒 | 人の自由を広げ、 |
| カット07 | 9.00–10.16秒 | 人の心を動かすために。 |

- 歌／ジングルの歌詞、効果音、BGM は書き起こしません
- 音声トラックが無い動画では自動的にスキップします
- 聞き取りは1本あたり **APIリクエスト1回**（音声はモノラル16kHzのFLACに圧縮して送ります）

精度の実測（合成音声の読み上げ位置と比較）:

| 正解の位置 | 聞き取った位置 | テキスト |
|---|---|---|
| 1.00秒 | 0.98秒 | 新しい季節が始まります |
| 5.50秒 | 5.48秒 | 見たことのない景色へ |
| 11.00秒 | 10.98秒 | この夏、あなたの毎日が変わる |

## コンテPPTX

1ページあたりのカット数を **列 × 行** で指定できます（既定は **4列 × 2行 = 8カット/ページ**）。

**レイアウトは固定値ではなく、実際の文章量から毎回計算します。**

1. 各カットのナレーション／ト書きが「その列幅で何行になるか」を数える
2. 行ごとに必要な高さを出す。**誰も書いていない要素は領域そのものを作らない**
   （ナレーションが無い行はその分だけ絵が大きくなる）
3. 全ページが収まる範囲で、**絵がいちばん大きくなる幅**を探す
4. 余った縦横の余白は行間・列間に配って全体を均す

文字サイズ（ナレーション・ト書き・番号・タイムコード）も列幅から自動で決まります。

グリッド別の絵の大きさ（16:9素材の場合）:

| グリッド | 絵の大きさ | 列幅の使用率 |
|---|---|---|
| 3列×2行 | 3.91 × 2.20 インチ | 95% |
| 4列×2行 | 3.06 × 1.72 インチ | 100% |
| 5列×3行 | 2.23 × 1.26 インチ | 92% |
| 2列×4行 | 3.30 × 1.86 インチ | 100% |

> 5列×3行は以前 0.84インチまで縮んでいました（文字の枠が常に2行分を確保して
> 行の高さの76%を占めていたため）。現在は **2.7倍** の大きさです。

- 絵の**外・左上に**カット番号（囲みなし、数字だけ）
- 絵の**下に**、上から順に
  1. **ナレーション**（黒）
  2. 少し空けて **ト書き**（ナレーションより **2pt小さく・グレー50%**）
  3. **タイムコード / 尺**
- タイムコードは **Premiere Pro と同じ `HH:MM:SS:FF`**（例 `00:00:05:07`）
  - フレームは 0 から数え、fps に達したら次の秒へ繰り上がります
  - fps は素材を解析した実測値を使います（23.976fps → 1秒 = 24フレーム）
- **行数 > 列数のときはスライドが自動で縦向き**になります（絵コンテ用紙に近い形）
  - 4列×2行 → 横向き（16:9）
  - 2列×4行 → 縦向き

書体は「Hiragino Kaku Gothic ProN」を欧文・和文の両方に指定しているので、
PowerPoint・Keynote どちらで開いても日本語が化けません。

## カット表Excel

コンテPPTXと同時に、同じフォルダに **`動画名_カット表.xlsx`** ができます。
カット数ぶんの行が上から下に並び、列は左から順に:

| 列 | 中身 |
|---|---|
| カット番号 | 1, 2, 3 … |
| キャプチャ画像 | 書き出した絵（セルに貼り込み） |
| ナレーション | 聞き取ったナレーション |
| ト書き | AIが書いたト書き |
| タイムコード | 上段が位置、下段が尺 |
| **クライアントFB** | **空欄**（記入用） |
| **修正ポイント** | **空欄**（記入用） |
| **備考・素材など** | **空欄**（記入用） |

- 記入用の3列はうっすら色を付けて、読む列と書く列を見分けられるようにしています
- 見出し行を固定してあるので、下にスクロールしても項目名が見えます
- 印刷時は横向き・横幅1ページに収まり、各ページに見出し行が入ります
- 書体は macOS・Windows どちらにもある **游ゴシック** を指定しているので、
  クライアントに渡しても文字が置き換わりません
- 設定の「カット表Excel」で ON/OFF できます

## AI（Gemini）の設定

### APIキー（Gemini のみ対応）

https://aistudio.google.com/apikey で取得したキーを「Gemini API キー」欄に貼って
**「設定」** を押してください。保存と接続確認を同時に行います。

**「削除」** を押すと確認ダイアログが出て、OKすると保存済みのキーを消します。

> **キーはアプリの中には入っていません。**
> macOS は `~/Library/Application Support/CutListMaker/config.json`、
> Windows は `%APPDATA%\CutListMaker\config.json`（各PCのユーザー領域）にだけ保存されます。
> **DMG や .app にはキーは一切含まれないので、そのまま人に渡して大丈夫です。**
> 受け取った人は自分のキーを入れて使います（未設定でも、AIなしのローカル判定だけで動きます）。

### モデル（2026年7月時点で実際にAPIで確認した状況）

既定は **`gemini-3.1-flash-lite`** です。

| モデル | 状況 |
|---|---|
| `gemini-3.1-flash-lite` | **既定**。速い（画像1枚あたり2〜3秒）。3.1系にフルのFlashは無く lite のみ |
| `gemini-3.5-flash` | 実在する。高性能だが混雑（503）に当たることがある |
| `gemini-3.6-flash` | 実在する。3.5より新しいが応答は遅め（8秒前後） |
| `gemini-3-flash-preview` / `gemini-2.5-flash` | フォールバック用 |

> `gemini-3.1-flash`（lite でないもの）は API に存在しません。
> 3.1系で選べるのは lite / image / tts のみのため、ご指定に一番近い `gemini-3.1-flash-lite` を既定にしています。

**混雑や未提供でエラーになったら、自動で次のモデルに切り替えて処理を続けます。**
「接続確認」を押すと、そのキーで使えるモデルがモデル欄の候補に入ります。

### 使用量

CM1本（10カット）あたり **3〜4リクエスト**です。

- カット選定：8カットで1リクエスト（10カットなら2回）
- ト書き生成：12カットで1リクエスト（10カットなら1回）
- ナレーション聞き取り：動画1本につき1リクエスト

## 設定項目

| 項目 | 説明 |
|---|---|
| **AI判定** | OFF にすると完全ローカル処理（通信なし・ト書きは付きません） |
| **ト書き** | OFF にすると画像だけ書き出します（APIの消費が減ります） |
| **ナレーション** | OFF にすると音声認識をしません |
| **コンテPPTX** | 書き出しの ON/OFF と、1ページの列数・行数 |
| **カット検出の細かさ** | 既定 27。取りこぼす → 下げる（20前後）／ 分割されすぎる → 上げる（33〜40） |
| **書き出し形式** | PNG（無劣化）／ JPEG（軽い） |

## どうやって選んでいるか

1. **カット検出** — 隣接フレームのHSV差分（ハードカット）＋ 周囲比の突出判定（動きの多い映像）
   ＋ 数フレームかけて変わる転換（ディゾルブ・ワイプ）＋ 黒み／白味の出入り、を併用。
   そのうえで**境界の前後が本当に別の絵になっているか**を色分布で検証し、
   同じショット内の動きで割れたものを捨てる（実素材で 43 → 33 カットに是正）
2. **候補の一次選抜** — 各カットから最大9フレームを抜き、
   ピント（ラプラシアン分散）・露出・彩度・構図（勾配サリエンシーの重心と三分割法）・
   顔検出・動きブレ・カット内の位置、で採点して上位6枚に絞る
3. **AIによる決定** — 6枚を番号付きコンタクトシートにしてGeminiへ
4. **書き出し** — 選ばれた時刻を ffmpeg で**元解像度のまま**切り出し
5. **ト書き** — 書き出した絵をGeminiがもう一度見て、コンテのト書きを書く
5.5. **ナレーション** — 音声をGeminiに聞かせて時刻付きで書き起こし、始まるカットに割り当てる
6. **PPTX / XLSX** — 絵とト書きを並べたコンテと、記入欄つきのカット表を組む

AIが使えないとき（キー未設定・通信エラー・レート制限）は、
自動的にローカル採点の1位を採用して**必ず最後まで完走**します（ト書きは空欄）。

## うまくいかないとき

| 症状 | 対処 |
|---|---|
| カットが多く出すぎる | 「カット検出の細かさ」を **上げる**（33〜40） |
| 同じショットが分割される | 境界の前後で色分布を比べて自動的にまとめています。それでも割れる場合は細かさを上げてください |
| カットが取りこぼされる | 「カット検出の細かさ」を **下げる**（18〜22） |
| ト書きが付かない | ログに `⚠ ト書きの生成をスキップ` が出ていないか確認。APIの上限に当たっている場合はモデルを変える |
| AIが効いていない | 「接続確認」を押す。✗ならキーを取り直す |
| 「開発元を確認できない」と出る | アプリを右クリック →「開く」→「開く」 |
| 起動しない・固まる | メニューの「表示 → 開発者ツール」でエラーを確認できます |

対応形式：mp4 / mov / m4v / avi / mkv / mxf / mpg / mts / webm など ffmpeg が読めるもの。
